```matlab
%% 第一阶段：预先计算所有N个智能体的总成本
agent_costs = zeros(N, 1);
for i = 1:N
    tasks_i = OCFUtils.get_agent_tasks_fast(SC, i, tol);

agentutility = 0;
for idx = 1:length(task_list)
    curr_task = task_list(idx);

    // 计算联盟加权成本
    coalition_cost = 0;
```

- 预先计算**所有N个智能体的总成本**（包括它们参与的所有任务）
- 每个任务的coalition_cost是参与者的**全局总成本的加权和**
- 然后再按贡献比分摊效用

## 问题：成本重复计算

### 数值示例

**场景**：智能体1参与任务A和任务B

**智能体1的总成本**：
```
参与任务A和B，需要飞行到两个地点
t_fly = 50, t_wait = 10, t_exec = 60
total_cost = 50×1.0 + 10×0.5 + 60×1.0 = 115
```

#### 旧版本计算（正确）

```
任务A收益：r_1A × V_A × D_A = 0.5 × 800 × 0.8 = 320
任务B收益：r_1B × V_B × D_B = 0.5 × 1000 × 0.7 = 350
总收益：320 + 350 = 670

总成本：115（只计算一次）

效用：670 - 115 = 555
```

#### 新版本计算（问题）

```
agent_costs(1) = 115  // 预先计算的全局总成本

任务A：
  participants = [1, 2, 3]
  coalition_cost = r_1A × agent_costs(1) + r_2A × agent_costs(2) + r_3A × agent_costs(3)
                 = 0.4 × 115 + ... ≈ 46 + ... = 200（假设）
  U_A = 800 × 0.8 - 200 = 440
  u_1A = r_1A × U_A = 0.4 × 440 = 176  // 智能体1从任务A获得的效用

任务B：
  participants = [1, 4]
  coalition_cost = r_1B × agent_costs(1) + r_4B × agent_costs(4)
                 = 0.6 × 115 + ... ≈ 69 + ... = 150（假设）
  U_B = 1000 × 0.7 - 150 = 550
  u_1B = r_1B × U_B = 0.6 × 550 = 330  // 智能体1从任务B获得的效用

总效用：176 + 330 = 506
```

#### 对比

| 版本 | 总效用 | 差异 |
|------|--------|------|
| 旧版 | 555 | - |
| 新版 | 506 | **低49（-8.8%）** |

## 问题根源

**agent_costs(i)** 是智能体i参与**所有任务的总成本**。

但在计算每个任务的coalition_cost时，又把这个**全局总成本**按比例分摊进去。

**如果智能体参与多个任务**：
- 它的总成本115会在**每个任务中都被部分计入**
- 虽然每次只计入一部分（r_1A × 115, r_1B × 115），但：
  - 如果 r_1A + r_1B ≈ 1，总成本会被重复计算
  - 导致效用被低估

**举例**：
- 智能体1的总成本115主要是飞行到A和B的成本
- 在计算任务A时，`coalition_cost`包含了`r_1A × 115`
- 在计算任务B时，`coalition_cost`又包含了`r_1B × 115`
- 如果`r_1A=0.4, r_1B=0.6`，总共计入了`0.4×115 + 0.6×115 = 115`
- 看起来总量对了，但逻辑不对！

**逻辑错误**：
- agent_costs(1) = 115是智能体1的**全局总成本**
- 这个成本应该在智能体层面扣除一次
- 而不是在每个任务层面重复扣除

## 成本分摊机制的理论问题

### 问题1：agent_costs的语义混淆

```matlab
agent_costs(i) = t_fly_i * fuel + t_wait_i * wait_fuel + t_exec_i * beta;
```

这个cost是基于**当前SC**计算的，包含了智能体i参与的所有任务的成本。

但在计算任务m的coalition_cost时：
```matlab
coalition_cost = sum(r_im * agent_costs(i));
```

这相当于说："任务m的成本 = 参与者的全局总成本的加权和"

**逻辑矛盾**：
- 如果智能体1参与任务A、B、C
- 它的agent_costs(1)包含了飞到A、B、C的所有成本
- 但在计算任务A的成本时，不应该包含飞到B、C的成本
- 现在却按r_1A的比例把全部成本都算进去了

### 问题2：循环依赖

```
agent_costs 依赖 SC
→ coalition_cost 依赖 agent_costs
→ U_m 依赖 coalition_cost
→ 决策依赖 U_m
→ SC变化
→ agent_costs变化
```

这种循环依赖可能导致不稳定的优化过程。

## 结论

**问题不是对数vs线性的问题**，而是：

1. **新版引入的成本分摊机制有逻辑缺陷**
2. **agent_costs是全局总成本，但被当作任务边际成本使用**
3. **导致多任务参与被隐性惩罚**
4. **最终导致任务覆盖率降低**

**推荐方案**：回退到旧版本（第7-105行的逻辑），删除或注释掉第109-237行的新版本。
