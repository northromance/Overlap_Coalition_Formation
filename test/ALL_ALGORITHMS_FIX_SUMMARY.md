## 🔧 核心技术改进

### 1. 统一的可行性检查机制

**所有算法的决策点都调用 `validate_feasibility`：**

```matlab
[isFeasible, info, cost_data] = validate_feasibility(
    Value_data,      // 完整的智能体数据数组
    agents,          // 智能体数组
    tasks,           // 任务数组
    Value_Params,    // 全局参数
    agentID,         // 当前决策的智能体ID
    SC_candidate,    // 候选联盟结构
    true             // 启用队友检查
);
```

**检查内容：**
1. ✅ 非负约束检查
2. ✅ 携带量约束检查
3. ✅ 能量约束检查（飞行+等待+执行）
4. ✅ 队友可行性检查

---

### 2. 队友检查机制

**工作原理：**
```
当智能体 A 尝试加入/离开任务时：
  ↓
找出所有与 A 共同参与任务的队友
  ↓
对每个队友调用 validate_feasibility_simple
  ↓
如果任何队友会变得不可行 → 拒绝 A 的决策
  ↓
防止"时间因果"问题：后加入的智能体增加等待时间，
导致先加入的智能体能量超标
```

**效果：**
- SA_Value: 队友检查阻止数百次不可行决策
- Qi2023: 队友检查阻止数百次不可行决策
- Shi2024: 队友检查阻止数百次不可行决策（主要是 Agent 4）

---

### 3. 能量计算准确性

**修复前：**
```
能量 = 飞行能量 + 等待能量 + 0（执行能量漏算）
误差：20-40%
```

**修复后：**
```
能量 = 飞行能量 + 等待能量 + 执行能量
误差：< 0.1%（仅浮点误差）
```

**关键：** 统一使用小写 `t_exec_total`

## 🎓 经验教训

### 1. 变量命名一致性至关重要

**教训：** 大小写不一致（`T_exec_total` vs `t_exec_total`）导致执行能量漏算。

**建议：**
- 统一使用小写 + 下划线命名
- 函数签名与内部变量保持一致
- 使用代码审查工具检查

### 2. 分布式决策需要全局一致性保证

**教训：** 后续决策会影响之前的决策结果（时间因果问题）。

**解决：** 队友检查机制 - 在每次决策时检查是否会导致队友不可行。

### 3. 不同算法需要不同的集成方式

**教训：**
- SA_Value: 使用 join/leave 操作（内置检查）
- Qi2023: 使用 execute_exchange_operation（需手动添加检查）
- Shi2024: 使用 initial + optimize（需在多处添加检查）

**建议：** 统一的可行性检查函数，在不同算法的决策点正确集成。

### 4. MATLAB 索引陷阱

**教训：** `for t = vector'` 可能导致 `t` 是向量而非标量。

**建议：** 使用 `for idx = 1:length(vector)` 确保标量索引。

### 5. 参数传递的完整性

**教训：** 传入 `Value_data(agent_id)` 导致队友检查无法访问其他智能体数据。

**建议：** 传入完整的数据结构，让函数内部根据需要访问。
