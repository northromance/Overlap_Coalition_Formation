# 贪婪算法在重叠联盟博弈中的设计说明

## 1. 重叠联盟 vs 互斥联盟

### 互斥联盟（Disjoint Coalition）
```
任务1: [智能体1, 智能体2]  ← 分配资源后，这些资源被锁定
任务2: [智能体3, 智能体4]  ← 只能使用剩余的智能体
任务3: [智能体5, 智能体6]
```
- ? 每个智能体只属于1个联盟
- ? 资源物理互斥，用完就没了
- ? 无法充分利用智能体能力

### 重叠联盟（Overlapping Coalition）
```
任务1: [智能体1, 智能体2, 智能体4]
任务2: [智能体2, 智能体3, 智能体4]  ← 智能体2和4可以复用
任务3: [智能体1, 智能体3, 智能体5]  ← 智能体1和3可以复用
```
- ? 每个智能体可以参与多个任务
- ? 资源在时间维度上复用
- ?? 需要考虑时间冲突、能量限制

## 2. 当前贪婪算法的问题

### 代码问题位置
```matlab
% Com_Baseline/Greedy_Baseline_main.m 第87行
remaining_resources(i, k) = remaining_resources(i, k) - allocation;
```

### 问题分析
1. **资源递减**：每次分配后减少剩余资源
2. **互斥假设**：智能体1给任务A后，不能再给任务B
3. **与重叠联盟模型不符**：违背了资源复用的核心思想

### 导致的后果
- 智能体4参与8个任务，但每次只能贡献部分资源
- 后分配的任务资源不足
- 任务4完全没有资源（资源耗尽）

## 3. 重叠联盟中贪婪算法的正确设计

### 核心思想
```
不是资源的物理分配，而是资源的时间调度
```

### 设计方案A：完全资源复用（忽略时间冲突）
```matlab
% 每个任务都可以访问智能体的完整资源
for each 任务 j:
    for each 智能体 i:
        if 智能体i距离任务j近 && 智能体i有需要的资源:
            分配资源(无需减少remaining_resources)
            计算效用时考虑：
                - 任务价值 × 完成度
                - 距离成本
```

**优点**：简单，充分利用资源  
**缺点**：不考虑时间冲突，不现实

### 设计方案B：考虑时间窗口的资源复用 ?推荐
```matlab
% 为每个智能体维护时间线
agent_timeline[i] = []  % 智能体i的任务时间安排

for each 任务 j (按优先级排序):
    for each 智能体 i (按距离排序):
        # 检查时间可行性
        飞行时间 = distance / velocity
        执行时间 = task_duration
        总耗时 = 飞行时间 + 执行时间
        
        # 尝试插入时间线
        if 能找到空闲时间槽:
            加入联盟
            分配资源 = min(需求, 智能体拥有量)
            更新时间线
            计算能量消耗（考虑已有任务）
```

**优点**：现实，考虑时间约束  
**缺点**：复杂度较高

### 设计方案C：能量预算的资源复用
```matlab
% 为每个智能体维护能量预算
remaining_energy[i] = agent[i].total_energy

for each 任务 j (按优先级排序):
    for each 智能体 i (按距离排序):
        # 估算能量消耗
        energy_cost = 计算飞行能量 + 计算执行能量
        
        if remaining_energy[i] >= energy_cost:
            加入联盟
            分配资源 = agent[i].resources  # 完整资源
            remaining_energy[i] -= energy_cost
```

**优点**：平衡了复杂度和现实性  
**缺点**：忽略了精确的时间调度

## 4. 推荐实现：能量约束的贪婪算法

### 算法流程
```
输入：agents, tasks
输出：coalitionstru (M×N), agentresources (N×M×K)

1. 初始化
   - coalitionstru = zeros(M, N)
   - agentresources = zeros(N, M, K)
   - remaining_energy[i] = agents[i].total_energy  (对所有i)

2. 按任务优先级排序

3. 对每个任务 j:
   a. 按距离排序所有智能体
   b. 对每个智能体 i:
      - 计算加入联盟的能量成本
      - 如果 remaining_energy[i] >= 能量成本:
        * coalitionstru(j, i) = 1
        * agentresources(i, j, :) = agents(i).resources  # 完整资源
        * remaining_energy[i] -= 能量成本
      - 如果任务需求已满足，跳出
      
4. 计算总效用（考虑所有任务的资源满足度）
```

### 关键代码修改
```matlab
% 不再维护 remaining_resources
% 改为维护 remaining_energy

for idx = 1:M
    j = task_order(idx);
    
    % 按距离排序智能体
    [~, agent_order] = sort(distances);
    
    for agent_idx = 1:N
        i = agent_order(agent_idx);
        
        % 计算能量成本
        fly_dist = distances(i);
        fly_energy = fly_dist * agents(i).fuel;
        exec_energy = tasks(j).duration * agents(i).beta;
        total_energy = fly_energy + exec_energy;
        
        % 检查能量是否足够
        if remaining_energy(i) >= total_energy
            % 加入联盟
            coalitionstru(j, i) = 1;
            
            % 分配完整资源（可复用）
            agentresources(i, j, :) = agents(i).resources;
            
            % 扣除能量
            remaining_energy(i) = remaining_energy(i) - total_energy;
            
            % 检查任务需求是否满足
            allocated = squeeze(sum(agentresources(:, j, :), 1))';
            if all(allocated >= tasks(j).resource_demand)
                break;  % 任务需求已满足
            end
        end
    end
end
```

## 5. 效用计算差异

### 互斥联盟
```matlab
效用 = 任务价值 × 满足度 - 距离成本
（每个智能体只计算一次）
```

### 重叠联盟
```matlab
对每个任务:
    效用 = 任务价值 × 完成度 - Σ(智能体距离成本 + 能量成本)
    
总效用 = Σ 所有任务效用

注意：同一智能体参与多个任务，成本累加
```

## 6. 对比示例

### 场景
- 智能体1：资源[5, 3, 2]，能量100
- 任务A：需求[3, 2, 1]，距离10
- 任务B：需求[2, 1, 1]，距离15

### 互斥联盟（当前算法）
```
1. 任务A分配智能体1：[3, 2, 1]
   剩余资源：[2, 1, 1]
   
2. 任务B尝试分配智能体1：只能给[2, 1, 1]
   ? 可以完成任务B
   
智能体1总贡献：1个任务
```

### 重叠联盟（能量约束）
```
1. 任务A分配智能体1：[5, 3, 2] (完整资源)
   消耗能量：fly(10) + exec = 25
   剩余能量：75
   
2. 任务B分配智能体1：[5, 3, 2] (完整资源，复用)
   消耗能量：fly(15) + exec = 30
   剩余能量：45
   
智能体1总贡献：2个任务（能量允许的情况下）
```

## 7. 总结

在重叠联盟博弈中，贪婪算法应该：

1. **不减少资源**：`remaining_resources` → `remaining_energy`
2. **资源可复用**：每次分配完整资源，不是剩余资源
3. **能量约束**：通过能量预算限制参与数量
4. **时间意识**：（可选）考虑时间窗口冲突
5. **效用累加**：智能体参与多个任务，成本累加

这样既符合重叠联盟的理论模型，又保持了贪婪算法的简单高效特性。
