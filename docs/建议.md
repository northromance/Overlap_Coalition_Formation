● 现在有足够信息了。以下是具体建议，从影响最大到最小排列。

  ---
  建议一：降低 resource_confidence（最高影响）

  当前问题根源：resource_confidence = 0.7，uniform prior（0.33 each）代入
  calculate_demand_quantile 时：
  cumsum([0.33, 0.67, 1.0]) >= 0.7 → 取第3项 → 各资源的跨类型最大值
  belief_off 永远估计需求上界，等于给自己加了一层"安全兜底"。

  改为 0.5：
  cumsum([0.33, 0.67, 1.0]) >= 0.5 → 取第2项 → 各资源的跨类型中位数

  效果对比：

  ┌────────────────┬───────────────────────────┬─────────────────────────────────────┐      
  │                │ belief_off (uniform 0.33) │      belief_on (收敛后 > 0.95)      │      
  ├────────────────┼───────────────────────────┼─────────────────────────────────────┤      
  │ confidence=0.7 │ 估计 = 最大值（兜底充分） │ 估计 = 正确类型需求                 │      
  ├────────────────┼───────────────────────────┼─────────────────────────────────────┤      
  │ confidence=0.5 │ 估计 = 中位数（可能低估） │ 估计 = 正确类型需求（触发阈值更早） │      
  └────────────────┴───────────────────────────┴─────────────────────────────────────┘      

  以你的数据为例，k5 资源（各类型需求为 [1, 1, 6]）：
  - confidence=0.7 → belief_off 估计 6（最大值）
  - confidence=0.5 → belief_off 估计 1（中位数）→ type3 任务 k5 严重低估 → 任务完成率下降   

  注意：resource_confidence 被全局使用，修改会影响所有实验。可以在 Exp_Config.Ablation      
  里单独覆盖（需要在 Batch_Ablation.m 里注入到 Value_Params_base）。

  ---
  建议二：增大任务类型需求的差异（高影响）

  当前：三种类型需求上限 4/6/8，导致各类型需求在数值上重叠较多（比如三种类型的 k1 需求分别是
   3/3/5，差异小）。

  建议：

  % 在 Exp_Params.m 中修改
  task_type1_demand_max = 2;   % 低需求：所有维度 [0,2]
  task_type2_demand_max = 5;   % 中等需求：[0,5]
  task_type3_demand_max = 8;   % 高需求：[0,8]（保持不变）

  这样三种类型的需求分布几乎不重叠：type1 需求矮小，type3 需求高大，错判代价更大。

  ---
  建议三：降低 N/M 比（高影响，直接）

  当前：N=10, M=10，智能体数 = 任务数，资源相对充裕，over-allocation 代价低。

  建议（在消融实验专属配置里改，不影响其他实验）：

  % Exp_Params.m Batch_Ablation 部分
  Exp_Config.Ablation.N_VALUES = [6, 8, 10];   % 加入低N场景
  Exp_Config.Ablation.M = 12;                  % 任务更多

  N=6/M=12 时：
  - 总资源量 ≈ 6×2×6 = 72（期望）
  - 总需求 ≈ 12 × avg_demand → 资源严重不足
  - belief_off 的 over-allocation 浪费有限资源 → 有些任务得不到充分服务
  - belief_on 把有限资源精确导向正确任务 → 明显更优

  建议五：调整任务价值差异（中等影响）

  更准确，一旦正确识别高价值任务、优先分配资源，效用提升幅度更大。
